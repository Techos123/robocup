# X5 与运动下位机二进制串口通信协议

| 项目 | 内容 |
| --- | --- |
| 协议版本 | V2.1 |
| 生效日期 | 2026-10-11 |
| 协议类型 | 二进制帧协议 |
| 通信双方 | X5 上位机、运动控制下位机 |
| X5 节点 | `motion_serial_bridge` |
| 旧协议状态 | V1 ASCII 协议已废弃，不再兼容 |

## 1. 适用范围

本协议用于 X5 向运动控制下位机发送启动及 PID 重置、底盘线速度、角速度、停止和相对定角转向命令，并接收定角转向完成回执。

串口线上只允许本协议定义的二进制帧，不得发送 `START`、`VEL ...`、`STOP`、`TURN ...`、`TURN_DONE` 等 ASCII 文本行。

IMU 由下位机独立采集和使用。X5 不通过该串口发送 yaw 或其他 IMU 数据。

## 2. 物理层

| 参数 | 约定 |
| --- | --- |
| X5 接口 | USB 串口，默认 `/dev/ttyUSB0` |
| 下位机接口 | 通过 USB-UART 模块连接下位机 UART |
| 波特率 | `115200 bit/s` |
| 数据位 | 8 bit |
| 校验位 | 无（None） |
| 停止位 | 1 bit |
| 数据格式 | 8N1 |
| 硬件流控 | 无 |
| 软件流控 | 无 |

UART TTL 电平由实际 USB-UART 模块和下位机硬件决定。接线前必须确认是 3.3V 还是 5V，并确保双方电平兼容、GND 共地、TX/RX 交叉连接。

## 3. 帧格式

每帧结构如下：

| 偏移 | 字段 | 长度 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 帧头 | 2 byte | `uint8[2]` | 固定为 `0xAA 0x55` |
| 2 | 命令字 CMD | 1 byte | `uint8` | 见命令表 |
| 3 | 数据长度 LEN | 1 byte | `uint8` | DATA 的字节数，范围 `0..255` |
| 4 | 数据区 DATA | N byte | byte array | 由命令字决定 |
| 4+N | CRC | 2 byte | `uint16` | CRC-16/Modbus，低字节先发送 |

总帧长度：

```text
FRAME_SIZE = 2 + 1 + 1 + LEN + 2 = LEN + 6 byte
```

帧结构示意：

```text
+--------+-----+-----+----------+----------+
| AA 55  | CMD | LEN | DATA...  | CRC_L/H  |
+--------+-----+-----+----------+----------+
  2 byte   1B    1B     LEN B       2B
```

本协议没有换行符或其他帧尾。接收方必须根据帧头和 LEN 判断完整帧长度。

## 4. 字节序与数据类型

- 所有多字节数值均使用小端序（Little-Endian）。
- 浮点数采用 IEEE-754 单精度 `float32`，长度固定为 4 byte。
- CRC 按低字节、再高字节的顺序发送。
- 浮点参数必须是有限值，禁止 `NaN`、`+Inf` 和 `-Inf`。

例如 `float32 0.3` 的小端字节为：

```text
9A 99 99 3E
```

## 5. CRC-16/Modbus

| 参数 | 数值 |
| --- | --- |
| 算法 | CRC-16/Modbus |
| 初始值 | `0xFFFF` |
| 多项式 | `0xA001`（反射形式） |
| 最终异或值 | `0x0000` |
| 计算范围 | `CMD + LEN + DATA` |
| 是否包含帧头 | 否 |
| 发送顺序 | CRC 低字节在前，高字节在后 |

标准校验向量：

```text
输入 ASCII 字节: 31 32 33 34 35 36 37 38 39  ("123456789")
CRC 计算结果:   0x4B37
线上发送顺序:   37 4B
```

下位机可参考以下 C 实现：

```c
#include <stddef.h>
#include <stdint.h>

uint16_t crc16_modbus(const uint8_t *data, size_t length)
{
    uint16_t crc = 0xFFFF;

    for (size_t i = 0; i < length; ++i) {
        crc ^= data[i];
        for (uint8_t bit = 0; bit < 8; ++bit) {
            if (crc & 0x0001) {
                crc = (crc >> 1) ^ 0xA001;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc;
}
```

调用时，指针应指向 CMD，长度应为 `2 + LEN`，即 CMD、LEN 和 DATA 的总长度。

## 6. 坐标系与单位

运动方向遵循 ROS `geometry_msgs/Twist` 的底盘坐标约定：

| 字段 | 单位 | 正值方向 | 负值方向 |
| --- | --- | --- | --- |
| `linear_x` | `m/s` | 前进 | 后退 |
| `angular_z` | `rad/s` | 左转、逆时针 | 右转、顺时针 |
| `angle_deg` | `deg` | 相对左转、逆时针 | 相对右转、顺时针 |

协议层不定义机械安全范围。下位机必须根据电机和底盘能力对速度及转角进行合法性校验和限幅。

## 7. 命令表

| 命令字 | 方向 | 名称 | LEN | DATA | 回执 |
| --- | --- | --- | --- | --- | --- |
| `0x01` | X5 -> 下位机 | 速度指令 VEL | 8 | `linear_x(float32) + angular_z(float32)` | 无 |
| `0x02` | X5 -> 下位机 | 停止指令 STOP | 0 | 无 | 无 |
| `0x03` | X5 -> 下位机 | 定角转向 TURN | 4 | `angle_deg(float32)` | `0x83` |
| `0x04` | X5 -> 下位机 | 启动 / PID 重置 START | 0 | 无 | 无 |
| `0x83` | 下位机 -> X5 | 转向完成 TURN_DONE | 0 | 无 | 无 |

### 7.1 启动 / PID 重置 START（0x04）

START 没有 DATA，固定 `LEN = 0x00`，完整帧为：

```text
AA 55 04 00 03 70
```

其中 CRC 对 `04 00` 计算，结果为 `0x7003`，线上低字节先发送为 `03 70`。START 无回执。

下位机每次上电或复位后的启动与重置规则：

1. 初始化结束后底盘保持 `DISABLE`，启动状态为 `WAITING`，继续采集 IMU、执行周期控制和发送零力矩。
2. X5 在下位机初始化完成后、发送运动命令前，发送第一条 START。
3. 下位机收到第一条合法 START 后记录启动请求，状态进入 `PENDING`；主循环使用当前有效 yaw（单位 `deg`）更新目标角，重置轮速 PID，然后使能底盘并将启动状态置为 `COMPLETE`。
4. 如果 IMU 暂时无效，底盘保持 `DISABLE`，启动请求保留；姿态恢复有效后完成上述首次启动流程，不要求 X5 重发 START。
5. 第一条 START 前收到的 VEL、TURN 不执行也不缓存。第一条 START 后收到的 VEL、TURN 按现有速度/转向互斥规则保存，底盘使能后才执行；START 与后续命令粘包时也遵循此顺序。
6. `PENDING` 和 `COMPLETE` 期间收到的后续合法 START 均记录 PID 重置请求，由主循环处理；重置请求本身不改变启动状态、不重新锁定航向、不清除已保存的线速度命令 `V`，也不取消待执行或执行中的 TURN。`PENDING` 期间的首次启动仍须等待有效姿态，并按第 3 条锁定一次航向。
7. 主循环处理 PID 重置请求时，将航向 PID 和四个车轮速度 PID 的输出、历史输出、历史误差、积分累计及目标/反馈历史清零，并通过零力矩输出路径同步清除电机输出和 CAN 发送缓冲。处理重置的当轮主循环跳过常规 PID 控制计算，避免零输出在发送前被覆盖；下一次控制周期按保留的运动目标恢复计算。
8. 同一轮主循环处理之前收到的多个 PID 重置请求可以合并为一次处理。PID 重置本身不要求 IMU 有效，也不绕过首次启动等待有效姿态的要求。
9. STOP 与 START 独立：STOP 不取消待处理的启动请求，也不清除已启动状态。启动后的 STOP 只停止运动，后续直接发送 VEL 或 TURN 即可，无需再次发送 START。

这里的“清零”指 PID 的内部状态及当轮控制输出，不清除底盘的目标航向或运动任务。下一次控制周期会用目标和最新反馈重新计算实际误差及输出；只要仍有速度或航向偏差，误差和输出就可能重新非零。

标准启动和停止后恢复时序：

```text
下位机初始化完成，底盘DISABLE
X5 -> 下位机: 0x04 START（本次上电的第一条START）
下位机: 等待有效姿态 -> 当前yaw写入目标角 -> 重置轮速PID -> 使能底盘
X5 -> 下位机: 0x01 VEL 或 0x03 TURN
X5 -> 下位机: 0x02 STOP
X5 -> 下位机: 0x01 VEL 或 0x03 TURN（恢复运动无需再次发送START）
```

后续 START 重置时序：

```text
下位机已启动，正在按现有速度或TURN目标运动
X5 -> 下位机: 0x04 START
下位机: 记录PID重置请求，保留目标航向、速度命令和TURN任务
下位机主循环: 清PID状态及电机发送输出 -> 跳过本轮常规控制 -> 发送零力矩
下位机下一次控制周期: 按保留的运动目标和最新反馈恢复控制
```

首次 START 用于启动，后续 START 用于 PID 重置，两者都没有回执，也不改变第 12 节 X5 的转向互斥状态。下位机复位后需要重新发送首次 START；仅上位机重连不会重置下位机的已启动状态，此时再次发送 START 会触发 PID 重置。

## 8. 速度指令 VEL（0x01）

### 8.1 DATA 定义

| DATA 偏移 | 长度 | 类型 | 字段 | 单位 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 0 | 4 byte | `float32` | `linear_x` | `m/s` | 底盘 X 轴线速度 |
| 4 | 4 byte | `float32` | `angular_z` | `rad/s` | 底盘 Z 轴角速度 |

固定 `LEN = 0x08`，完整帧长度为 14 byte。

### 8.2 示例：linear=0.3 m/s，angular=0.5 rad/s

```text
AA 55 01 08 9A 99 99 3E 00 00 00 3F B2 04
```

分解：

| 字节 | 含义 |
| --- | --- |
| `AA 55` | 帧头 |
| `01` | VEL 命令字 |
| `08` | DATA 长度 8 byte |
| `9A 99 99 3E` | `linear_x = 0.3` |
| `00 00 00 3F` | `angular_z = 0.5` |
| `B2 04` | CRC `0x04B2`，低字节先发 |

### 8.3 发送频率

- 相同速度帧最小重复发送间隔为 `0.05s`，最高约 `20Hz`。
- 线速度或角速度变化时立即发送新帧。
- 下位机不需要回复速度帧。

## 9. 停止指令 STOP（0x02）

STOP 没有 DATA，固定 `LEN = 0x00`，完整帧为：

```text
AA 55 02 00 00 D0
```

其中 CRC 为 `0xD000`，线上低字节先发送为 `00 D0`。

当 ROS `/cmd_vel.linear.x` 和 `/cmd_vel.angular.z` 的绝对值均小于 `0.0001` 时，X5 发送 STOP。

下位机收到后应将底盘运动目标置零。STOP 是普通软件停止命令，不是带独立硬件回路的安全急停。

STOP 不使已启动的底盘回到等待 START 状态，也不取消尚未完成的 START 请求；停止后恢复运动无需再次发送 START。

## 10. 定角转向 TURN（0x03）

### 10.1 DATA 定义

| DATA 偏移 | 长度 | 类型 | 字段 | 单位 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 0 | 4 byte | `float32` | `angle_deg` | `deg` | 相对当前车身方向的目标转角 |

固定 `LEN = 0x04`，完整帧长度为 10 byte。

角度规划、IMU 闭环、减速和最终停止全部由下位机实现。X5 只发送一次目标转角。

### 10.2 示例：右转 90 度

`angle_deg = -90.0`：

```text
AA 55 03 04 00 00 B4 C2 07 79
```

分解：

| 字节 | 含义 |
| --- | --- |
| `AA 55` | 帧头 |
| `03` | TURN 命令字 |
| `04` | DATA 长度 4 byte |
| `00 00 B4 C2` | `angle_deg = -90.0` |
| `07 79` | CRC `0x7907`，低字节先发 |

## 11. 转向完成 TURN_DONE（0x83）

下位机仅在转角已经完成且底盘进入稳定停止状态后发送 `0x83`。

TURN_DONE 没有 DATA，固定 `LEN = 0x00`，完整帧为：

```text
AA 55 83 00 60 80
```

其中 CRC 为 `0x8060`，线上低字节先发送为 `60 80`。

要求：

- `CMD` 必须为 `0x83`。
- `LEN` 必须为 `0x00`。
- CRC 必须正确。
- 带非空 DATA 的 `0x83` 帧不会解除 X5 转角锁定。
- 当前协议未定义失败回执。未收到合法 `0x83` 时，X5 会持续等待。

## 12. 控制互斥状态机

以下描述 X5 的转向互斥逻辑；运动任务开始前须先发送第 7.1 节的首次 START。后续 START 仅请求 PID 重置，不解除转向锁定。

| 当前状态 | 事件 | X5 行为 | 下一状态 |
| --- | --- | --- | --- |
| `NORMAL` | 收到 `/cmd_vel` | 发送 `0x01` 或 `0x02` | `NORMAL` |
| `NORMAL` | 收到合法 TURN 请求 | 发送一次 `0x03` | `TURN_ACTIVE` |
| `TURN_ACTIVE` | 收到 `/cmd_vel` | 丢弃，不发送速度或停止帧 | `TURN_ACTIVE` |
| `TURN_ACTIVE` | 收到新的 TURN 请求 | 丢弃，不抢占当前转向 | `TURN_ACTIVE` |
| `TURN_ACTIVE` | 收到合法 `0x83` | 解除锁定，恢复速度通道 | `NORMAL` |
| `TURN_ACTIVE` | 收到错误 CRC 或其他命令 | 丢弃或仅记录，不解除锁定 | `TURN_ACTIVE` |

主任务的标准转向时序：

```text
X5 -> 下位机: 0x02 STOP
X5 -> 下位机: 0x03 TURN(angle_deg)
下位机使用自身 IMU 完成转向并稳定停止
下位机 -> X5: 0x83 TURN_DONE
X5 恢复发送 0x01 VEL
```

进入 `TURN_ACTIVE` 后，当前实现也会抑制新的 STOP。安全急停应使用独立硬件链路，不应依赖本协议抢占 TURN。

## 13. 接收解析要求

UART 是字节流，单次接收不保证对应一整帧。下位机解析器必须支持半包、粘包和噪声字节。

推荐流程：

1. 将收到的字节追加到循环缓冲区。
2. 搜索连续帧头 `AA 55`，丢弃帧头之前的噪声。
3. 缓冲区不足 4 byte 时继续等待。
4. 读取 LEN，计算总长度 `LEN + 6`。
5. 缓冲区不足完整帧长度时继续等待。
6. 对 `CMD + LEN + DATA` 计算 CRC。
7. CRC 正确则分发命令，并从缓冲区移除整帧。
8. CRC 错误则至少丢弃当前帧头的第一个字节，再重新搜索 `AA 55`。

不要假设一次 UART DMA、中断或 `read()` 调用恰好收到一帧。

## 14. 异常处理

### 14.1 X5 侧已实现

- 拒绝 `NaN`、无穷大和超出 float32 表示范围的速度或转角。
- 转向期间抑制速度帧和新的转角请求。
- 支持半包和粘包解析。
- CRC 错误帧不执行，并重新搜索帧头。
- 未知命令帧只记录，不改变运动状态。

### 14.2 下位机侧要求

- CMD 对应的 LEN 必须严格匹配命令表。
- START 必须为 `0x04`、`LEN = 0` 且 CRC 正确；非法 START 不改变启动状态，也不触发 PID 重置。
- CRC 错误、未知命令、长度错误和非法浮点数必须丢弃。
- 对速度和转角执行符合硬件能力的限幅。
- 格式错误的帧不得触发上一条命令重复执行。
- 只有真实完成转角并稳定停止后才能发送 `0x83`。

## 15. IMU 约定

- IMU 完全由下位机负责采集和处理。
- X5 不订阅 `/imu/data_raw`。
- 本协议没有 YAW 命令字。
- 下位机可使用 IMU 完成 `0x03` TURN 的角度闭环。

## 16. ROS 接口映射

ROS 节点之间仍使用 ROS 消息；只有 X5 与下位机之间的串口是二进制协议。

| ROS 接口 | 类型 | 串口映射 |
| --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | `0x01` VEL 或 `0x02` STOP |
| `/motion_cmd` | `std_msgs/msg/String` | X5 内部解析 `TURN <角度>` 后编码为 `0x03` |
| `/motion_status` | `std_msgs/msg/String` | 收到合法 `0x83` 后发布内部状态 `TURN_DONE` |
| `/motion_status_raw` | `std_msgs/msg/String` | 发布合法串口帧的十六进制字符串，供调试使用 |

V2.1 要求 X5 在任务启动流程中发送首次 START 二进制帧；之后可按需发送 START 请求 PID 重置。本文不新增 ROS 话题，也不将 START 映射为 `/cmd_vel` 或 STOP 的副作用。

## 18. 版本兼容性

- V2.1 新增 `0x04` START；原 V2.0 的 VEL、STOP、TURN、TURN_DONE 帧格式保持不变。
- 下位机初始化后默认失能；未增加 START 发送的旧版 X5 无法启动新版下位机的底盘。
- X5 与下位机必须同时支持 V2.1 的首次 START 启动流程后再进行实车测试。
- 本次修订保持 V2.1 和所有帧格式不变，后续 START 的语义由忽略改为 PID 重置。旧版下位机可能忽略后续 START；X5 重发或重连补发 START 时，应确认下位机支持的重置行为。
- V1 ASCII 行协议已经删除。
- X5 不会识别下位机返回的 ASCII `TURN_DONE`。
- 下位机也不应等待 ASCII `START`、`VEL`、`STOP` 或 `TURN`。
